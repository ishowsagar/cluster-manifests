---- Kubernates -----

# Minikube

- It is for development (local development) learning only to simulate the working of kubernates cluster
- It creates simulated cluster to mock the working of the real cluster.

# kubectl

- It is command line tool to interact with minikube's cluster, so -> it talks to minikube cluster.

# - Node

- Node is just like one single entity in the cluster where pods are provisioned.
- node in simpler terms it could be any vm/cloud-machine/local-machine

# Deployment

application is deployed with deployment which is deployment manifest yml which is undertaken by -> replica set ( also known as RS) -> creates replicas of pods (wrapper -> of service (img/application)) -> no of pods specified in the deployment manifest
But this is limited to whoever who has access to the minikube cluster, who can ssh into and access it but for exposure to the outside world -> we wrap it up in service which forwards request to deployment

# Service

Service has elastic ip address, so instead of req on each pod , req is made on EIP Adrr generated by CCM -> req -> forwarded to pods ( handled by kube proxy in worker node) -> serve application.
